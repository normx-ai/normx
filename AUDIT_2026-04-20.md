# Audit Normx — 2026-04-20

Application React 19 + Express + PostgreSQL + Qdrant (comptabilité, paie, états, révision, assistant IA).
Audit réalisé sur trois axes : sécurité, performance, duplication de code.

Légende d'état : `[x]` = corrigé / `[ ]` = en attente / `[~]` = ajusté (diagnostic révisé à l'analyse).

Corrections committées : `20e0e5e` (sprint 1 & 2), `8d6e84f` (docs), `8e4dbb5` (vague 3 : taxation, formatDate, types backend, CORS, Qdrant timeout), vague 4 en cours (import TVA SQL).

## 1. Sécurité

### Critique

- [~] JWT `/me` sans vérification de signature RS256 (pas seulement `exp`)
  - Diagnostic révisé : `/callback` et `/refresh` reçoivent le token directement de Keycloak via TLS, donc authentiques. Le vrai risque était sur `/me` qui acceptait un cookie forgé.
  - Fait : `server/routes/auth.ts:162` passe par `authenticateToken` (JWKS + RS256 + iss + exp).

- [x] XSS via `dangerouslySetInnerHTML` sur exports Excel
  - `src/etats/ResultatFiscal.tsx:597`, `CompteResultatSYSCOHADA.tsx:576`, `TFT_SYSCOHADA.tsx:620`, `BilanSYSCOHADA.tsx:441`
  - Fait : `src/lib/excelExport.ts` → helper `escapeHtml` appliqué sur `entiteName`, `entiteNif`, `title`, `subtitle`, `headers`, `row.libelle`, `row.ref`, `exerciceAnnee`, `dureeMois`, valeurs string.

- [~] Cookie CSRF `httpOnly: false`
  - Diagnostic révisé : ce réglage est exigé par le pattern double-submit, le frontend lit le cookie via `document.cookie` (src/csrf-fetch.ts:16, src/api.ts:10). Défense réelle = `sameSite: 'strict'` déjà en place. Pas de régression accepté.
  - Fait : `server/middleware/csrf.ts:22` annoté pour documenter le choix.

### Haute

- [x] DB SSL désactivé par défaut en prod
  - Diagnostic révisé : l'infra prod utilise PostgreSQL sur réseau Docker interne (`normx-db`), pas d'exposition externe. SSL opt-in est correct.
  - Fait : `server/db.ts` émet un `logger.warn` au démarrage si `NODE_ENV=production` et host externe sans `DB_SSL=true`.

- [ ] Message d'erreur verbeux sur `ANTHROPIC_API_KEY`
  - `server/services/assistant.chat.ts:11-12`, `server/services/ocr-import.service.ts:13-14`
  - Non traité : non critique. À faire : validation au startup + erreur générique côté client.

### Moyenne

- [ ] Vérifier qu'aucun stack trace ne fuit au client (comportement actuel OK, à garder sous surveillance).
  - `server/index.ts:213-215`

- [x] CORS fallback `localhost` si `ALLOWED_ORIGINS` non défini ; garde anti-`*` à ajouter.
  - Fait : `server/index.ts` throw au démarrage si `ALLOWED_ORIGINS` contient `*` (config invalide fail-fast).

### Propre (inchangé)

SQL paramétré, Helmet, rate limit auth 10/h, JWT RS256 via JWKS Keycloak, Multer magic bytes, pas d'`eval`, cookies `httpOnly: true` sur tokens d'accès/refresh.

## 2. Performance

### Critique

- [x] Pagination absente ou `LIMIT 5000` hardcodé
  - `server/services/ecritures.service.ts:360` (`getGrandLivreTiers`)
  - `server/services/ecritures.service.ts:484` (`getBalanceAgee`)
  - `server/services/ecritures.service.ts:607` (`getEcheancier`)
  - Fait : paramètre `{ limit, offset }` injecté via `getPagination(req, 1000, 5000)` dans les 3 routes. Plafond max toujours à 5000 pour compatibilité existante.

- [x] Import TVA : deux `SELECT` massifs sur comptes 443x/445x puis calculs JS
  - Fait : `server/services/tva.service.ts` — les deux `SELECT + boucle JS + bulk INSERT` remplacés par des `INSERT ... SELECT` qui calculent `montant_taxe`, `taux_taxe` (CASE 4435%/4455% → 5 sinon 18), `montant_net` (ROUND) et `avoir` en SQL. Filtre `|montant| >= 0.01` dans le WHERE. Plus de rapatriement Node, gain attendu ×5 sur gros volumes.

### Important

- [x] Calculs Bilan sans `useMemo`
  - `src/etats/BilanSMT.tsx:154-159`
  - Fait : `useMemo` sur `computeActif`, `computePassif`, `computeResultatNet` avec déps `[lignesN]`/`[lignesN1]`.

- [x] `readFileSync` runtime sur KB et templates SQL
  - Diagnostic révisé : `assistant.agents.ts` charge déjà les KB une seule fois au module-load (const module-level), pas à chaque requête. Acceptable.
  - `server/services/tenant.service.ts` : templates SQL cachés en mémoire (lecture unique au premier tenant créé au lieu d'à chaque appel).
  - `server/routes/assistant.ts:183` (`/fonctionnement-comptes`) : le vrai problème, lisait ~plusieurs Mo de JSON à chaque requête. Refactoré en cache lazy module-level `getFonctionnementArticles()`.

- [x] Qdrant + fallback KB séquentiels
  - Fait : `server/services/assistant.search.ts` enveloppe `qdrantModule.search` dans `Promise.race` avec timeout 2 s (configurable via `QDRANT_TIMEOUT_MS`). Sur timeout → `null` → fallback mots-clés immédiat.

- [~] Index `CREATE INDEX` des migrations 003-005 absents de `sql/schema.sql`
  - Diagnostic révisé : `sql/schema.sql` est un fichier hérité non utilisé. Le vrai template est `server/migrations/002-tenant-schema-template.sql` et contient déjà tous les index (lignes 326-351). Nouveaux tenants non impactés.
  - Fait : `sql/schema.sql` annoté comme hérité.

### Mineur

- [ ] `recalcTotals` TVA (`tva.service.ts:41-62, 214, 269, 302`) — index `declaration_id` présent, laissé tel quel.
- [ ] Styles inline dans grosses tables (`BilanSMT.tsx:190-200`) — à externaliser en classes CSS.
- [x] `staleTime` plan comptable 1h → 24h
  - Fait : `src/lib/queries.ts:94` → `staleTime` et `gcTime` à `24 * 60 * 60 * 1000`.

### Propre (inchangé)

React Query configuré, bulk inserts paramétrés, pagination existante sur écritures/balance principale, pas de lodash/moment massifs, transactions ACID.
